رمزهای کلاسیک

Caesar Cipher

رمزگذاری
C = (p + k) mod 26
رمزگشایی
p = (C - k) mod 26
فقط 25 کلید ممکن ← آسیب‌پذیر به Brute Force. سه ویژگی که حمله را ممکن می‌کند: ۱) الگوریتم شناخته‌شده ۲) کلید کم ۳) زبان قابل تشخیص

Monoalphabetic Cipher

هر حرف دلخواه با حرف دیگری جایگزین. تعداد کلیدها: 26! — اما آسیب‌پذیر در برابر تحلیل فراوانی.

Digrams: th (رایج‌ترین)Trigrams: the (رایج‌ترین)

Playfair Cipher

رمزگذاری دو حرفی با ماتریس 5×5 — I و J یکی حساب می‌شوند.

  • دو حرف در یک سطر → حرف سمت راست
  • دو حرف در یک ستون → حرف زیرین
  • غیر این صورت → گوشه‌های مستطیل تشکیل‌شده
مزیت: پنهان‌سازی فراوانی تک‌حرفی، 676 ترکیب دوحرفی
عیب: با چند صد حرف قابل شکستن

Hill Cipher

مبتنی بر ضرب ماتریسی پیمانه 26. ماتریس 3×3 فراوانی تک‌حرفی و دوحرفی را پنهان می‌کند.

مزیت: مقاوم در برابر حمله Ciphertext-Only
عیب: ضعیف در برابر Known-Plaintext Attack

One-Time Pad

کلید کاملاً تصادفی هم‌طول متن، فقط یک‌بار استفاده → Unconditionally Secure

  • عیب ۱: تولید کلید زیاد
  • عیب ۲: مشکل توزیع کلید
  • عیب ۳: هر کلید فقط یک‌بار قابل استفاده

Feistel Cipher

  • ترکیب متناوب Substitution + Permutation در چندین دور
  • ورودی: 2w بیت ← تقسیم به LE₀ و RE₀
  • پس از Substitution، نیمه‌های چپ و راست جابه‌جا می‌شوند
  • رمزگشایی مشابه رمزگذاری است — ترتیب کلیدها معکوس

اجزاء DES

  • 8 عدد S-box: ورودی 6 بیت → خروجی 4 بیت

Avalanche Effect در DES

  • تغییر یک بیت Plaintext: پس از 3 دور → 18 بیت تفاوت، نهایی → 32 بیت
  • تغییر یک بیت کلید → تقریباً نیمی از بیت‌های Ciphertext تغییر می‌کند
امنیت DES: 2⁵⁶ کلید ممکن ← یک PC در حدود یک سال می‌تواند بشکند. کلیدهای 128 بیت یا بیشتر عملاً غیرقابل شکستن هستند.

مراحل هر دور AES
  • ۱
    SubBytes — جانشینی با S-Box (4 بیت چپ = سطر، 4 بیت راست = ستون)
  • ۲
    ShiftRows — جایگشت (سطر 1: بدون تغییر | سطر 2: چرخش 1 چپ | سطر 3: چرخش 2 چپ | سطر 4: چرخش 3 چپ)
  • ۳
    MixColumns — ضرب در ماتریس ثابت در GF(2⁸)
  • ۴
    AddRoundKey — XOR با کلید دور (تنها مرحله‌ای که از کلید استفاده می‌کند)
دور نهایی: فقط SubBytes + ShiftRows + AddRoundKey — بدون MixColumns
شروع رمزنگاری: AddRoundKey | رمزگشایی: کلیدها به ترتیب معکوس

ویژگی‌های مهم AES

  • ساختار Feistel ندارد — کل بلوک یکجا پردازش می‌شود
  • فقط AddRoundKey از کلید استفاده می‌کند
  • تمام مراحل برگشت‌پذیر هستند
  • کلید 128 بیتی به 44 واژه 32 بیتی گسترش می‌یابد
  • Avalanche Effect قوی‌تر از DES: پس از ۲ دور تقریباً نیمی از بیت‌ها تغییر می‌کنند

RSA — مشخصات و فرمول‌ها

معرفی: Ron Rivest, Adi Shamir, Len Adleman — سال 1978 | امنیت: دشواری تجزیه اعداد بزرگ

مراحل تولید کلید

  • ۱
    انتخاب دو عدد اول بزرگ p ≠ q
  • ۲
    محاسبه n = pq
  • ۳
    محاسبه φ(n) = (p-1)(q-1)
  • ۴
    انتخاب e که gcd(e, φ(n)) = 1 و e < φ(n)
  • ۵
    محاسبه d = e⁻¹ mod φ(n)
  • ۶
    کلید عمومی: PU = (e, n) | کلید خصوصی: PR = (d, n)
رمزگذاری
C = Mᵉ mod n
رمزگشایی
M = Cᵈ mod n
مثال: p=17, q=11 → n=187 | φ(n)=160 | e=7 → d=23 | PU=(7,187) | PR=(23,187)

Diffie-Hellman Key Exchange
  • اولین الگوریتم منتشرشده کلید عمومی
  • هدف: تبادل کلید مخفی مشترک — نه رمزگذاری پیام
  • امنیت: سختی محاسبه لگاریتم گسسته (Discrete Logarithm)

پارامترهای عمومی: عدد اول q، ریشه اولیه α

Alice

انتخاب Xₐ (خصوصی)
Yₐ = αˣᵃ mod q (عمومی)

Bob

انتخاب X_B (خصوصی)
Y_B = αˣᴮ mod q (عمومی)
Alice محاسبه می‌کند
K = Y_B^Xₐ mod q
Bob محاسبه می‌کند
K = Yₐ^X_B mod q
مثال: q=353, α=3, Xₐ=97, X_B=233
Yₐ = 3⁹⁷ mod 353 = 40 | Y_B = 3²³³ mod 353 = 248
K = 248⁹⁷ mod 353 = 40²³³ mod 353 = 160

Man-in-the-Middle Attack

  • مهاجم بین دو طرف قرار می‌گیرد — برای هر طرف وانمود می‌کند طرف مقابل است
  • دلیل آسیب‌پذیری: DH سازوکار احراز هویت ندارد
  • راه مقابله: امضای دیجیتال / گواهی کلید عمومی (CA)
ElGamal — مشخصات و الگوریتم

معرفی: T. ElGamal — 1984 | مبتنی بر Discrete Logarithm | کاربرد: DSS, S/MIME

تولید کلید

  • کلید خصوصی: Xₐ (۱ ≤ Xₐ ≤ q-2)
  • کلید عمومی: (q, α, Yₐ) که Yₐ = αˣᵃ mod q

رمزگذاری (Bob برای Alice)

انتخاب k تصادفی
C₁ = αᵏ mod q
C₂ = M × Yₐᵏ mod q
متن رمز: (C₁, C₂)

رمزگشایی (Alice)

K = C₁^Xₐ mod q
M = C₂ × K⁻¹ mod q

تابع هش

h = H(M)    ورودی: طول متغیر → خروجی: طول ثابت
هدف اصلی: یکپارچگی داده (Data Integrity) — هر تغییر حتی یک بیت باعث تغییر هش می‌شود
دو ویژگی تابع هش رمزنگاری
  • ۱
    One-Way Property: از h، یافتن M از نظر محاسباتی غیرممکن است (Preimage Resistance)
  • ۲
    Collision Resistance: یافتن x≠y با H(x)=H(y) غیرممکن است

⭐ Birthday Attack

در 23 نفر: احتمال روز تولد مشترک > 50%

نتیجه برای توابع هش: با 2^(n/2) نمونه از تابع هش n-بیتی، احتمال Collision > 50%

⚠️ امنیت واقعی هش n-بیتی: 2^(n/2) — نه 2^n

MAC (Message Authentication Code)

MAC = C(K, M)    ورودی: پیام + کلید مخفی → خروجی: بلوک ثابت کوچک
MAC محرمانگی ایجاد نمی‌کند. برای محرمانگی باید رمزنگاری جداگانه انجام شود.

امنیت MAC

پیچیدگی Brute Force: min(2ᵏ, 2ⁿ)   که k=طول کلید، n=طول MAC
برای امنیت مناسب: min(k, n) ≥ 128

HMAC

  • MAC مبتنی بر تابع هش رمزنگاری
  • استاندارد: FIPS 198
  • اجباری در IPsec، استفاده در SSL
  • مزیت: سرعت بالاتر از DES در نرم‌افزار
  • امنیت وابسته به امنیت تابع هش پایه

CCM (Counter with CBC-MAC)

مشخصات

  • استاندارد: NIST SP 800-38C
  • طراحی برای: IEEE 802.11 WiFi
  • اجزاء: AES + CTR + CMAC + کلید K
  • یک کلید واحد برای رمزگذاری و MAC

سه ورودی

  • P
    Plaintext — رمزگذاری + احراز هویت
  • A
    Associated Data — فقط احراز هویت (نه رمزگذاری، مثل Header)
  • N
    Nonce — مقدار یکتا برای هر پیام (جلوگیری از Replay Attack)
GCM (Galois/Counter Mode)
  • استاندارد: NIST SP 800-38D
  • مزایا: پردازش موازی، Throughput بالا، تأخیر کم
  • رمزگذاری با CTR Mode
  • Tag احراز هویت با ضرب در GF(2¹²⁸)
  • توابع: GHASH (هش کلیددار) و GCTR (نسخه CTR)
  • GMAC: نسخه فقط MAC از GCM

فرمول‌های همه فصل‌ها

Caesar: C = (p + k) mod 26 p = (C - k) mod 26 RSA Encrypt: C = Mᵉ mod n RSA Decrypt: M = Cᵈ mod n RSA φ(n): φ(n) = (p-1)(q-1) DH Public Key: Y = αˣ mod q DH Shared Key: K = Y_other^X_self mod q ElGamal Enc: C₁ = αᵏ mod q | C₂ = M × Yₐᵏ mod q ElGamal Dec: K = C₁^Xₐ mod q | M = C₂ × K⁻¹ mod q CBC: Cᵢ = E(K, Pᵢ ⊕ Cᵢ₋₁) first: C₁ = E(K, P₁ ⊕ IV) CTR: Cᵢ = Pᵢ ⊕ E(K, Tᵢ) 3DES: C = E(K₃, D(K₂, E(K₁, P))) [key = 168 bit] Birthday: Security of n-bit hash ≈ 2^(n/2) MAC Brute: Complexity = min(2ᵏ, 2ⁿ) → need min(k,n) ≥ 128
